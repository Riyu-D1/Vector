## Problem (from docs/STATUS-fw2.md, your own open question)
The motor controllers (B-G431B-ESC1) are powered from `+12V_MOT`, which is only live after relay K1 closes. The W1 state machine requires "all ESC heartbeats present" BEFORE it will close K1. The ESCs cannot send a heartbeat while unpowered, so the arm can never be armed (deadlock).

## Fix (firmware only; the PCB cannot change)
1. Change `firmware/shared/motor_en.c/.h` to a two-phase arm: Phase 1 (pre-arm) needs only: host handshake + ARM_MOTOR command + estop released + no bus-off. When satisfied, close K1 (MOTOR_EN high) and start a `esc_boot_window_ms` timer (default 1500 ms, a param). Phase 2: every configured ESC must send its first heartbeat inside that window, otherwise drop MOTOR_EN immediately, report reason ESC_BOOT_TIMEOUT, and require a fresh explicit ARM_MOTOR. After phase 2, the existing rule stays: loss of any ESC heartbeat for the alive window (400 ms), any estop, watchdog timeout, CAN bus-off or ESC fault drops MOTOR_EN at once, and re-arm needs an explicit host command.
2. The ESC firmware must power up with motor torque DISABLED and refuse torque until it receives an explicit NMT_ENABLE (already gated on calibration + homing: re-check the boot path in `firmware/joint-driver/joint_driver.ino` so no PWM output can occur before enable, including right after relay close).
3. Servos on bus A are on the unswitched rail? Check `~/Vector-wt/pcb13/pcb13/STATUS-pcb13.md` and `README.md` to see which rail J1/J4–J6/gripper servo power is on, and state the answer in the status. If the servos are on `+12V_MOT` too, apply the same boot-window logic to the servo ping (servos must answer a ping inside the window).
4. Update tests: `tests/test_motor_en.py` (ctypes) with new cases: pre-arm closes K1 without ESC heartbeats; ESC boot timeout drops it with the right reason; heartbeat inside the window keeps it; heartbeat loss later drops it; estop during the window drops it; re-arm requires an explicit command. Run the whole suite (`python3 -m pytest tests`) and paste the real pass count.
5. Rebuild both firmwares with PlatformIO and paste the SUCCESS lines with sizes.
